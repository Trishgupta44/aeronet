# Plan D: Final Package (Docs, Report, Slides, Offline Test, v1.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. This is a **guide**: you write the code.
> The roadmap (`2026-11-05-aeronet-v2-roadmap.md`) wins on any conflict.

**Goal:** deliver P17–P22 from the roadmap: READMEs, report, slides, synopsis, progress report, papers
guide and viva sheet, all with **numbers pulled from `results/summary.csv` by script**; then an offline
clean-copy test and the `v1.0` tag.

**Architecture:** the text is written as Markdown in `docs/deliverables_src/`. Numbers appear as
placeholders (`{{E2|pinn|50x25|rms_cp}}`), which a script fills from `summary.csv`. A missing number is a
**hard error**, never a blank. Small builders turn the Markdown into `.docx` (python-docx) and `.pptx`
(python-pptx). Output goes to `deliverables/` and PDFs to `deliverables/pdf/`.

**Tech stack:** python-docx 1.2, python-pptx 1.0.2 (both checked on this machine), Markdown, git.

**Prerequisite:** Plan C is complete (all `summary.csv` rows, `results/figures/*.png`, `results/tables.md`
and the screenshots in `docs/milestones/img/`).

## File map

| Path | Responsibility |
|---|---|
| `research/docs_build/numbers_fill.py` | `load_rows(csv)`, `lookup(rows, exp, method, mesh, column, case=None)`, `fmt(value, column)`, `fill(text, rows)` |
| `research/docs_build/build_docx.py` | `build(md_text, out_path, base_dir, font="Times New Roman", size=12)` |
| `research/docs_build/build_pptx.py` | `build(md_text, out_path, base_dir)` |
| `research/docs_build/build_all.py` | CLI that fills and builds every deliverable; `--check` only fills, to find missing numbers |
| `research/tests/test_docs_build.py` | unit tests for the three modules |
| `docs/deliverables_src/{report,slides,synopsis,progress,papers_guide,viva}.md` | the source text |
| `deliverables/*.docx`, `deliverables/3_Panel_Presentation.pptx`, `deliverables/pdf/` | the output (committed) |
| `README.md`, `app/README.md`, `docs/verification.md`, `docs/demo_script.md` | updated docs |

**Placeholder syntax:** `{{experiment|method|mesh|column}}` or `{{experiment|method|mesh|column|case}}`.
`lookup` must match **exactly one** row, otherwise it raises a KeyError naming the placeholder.
Formatting: rms, max and cd use 4 decimals; cl and cl_ref use 3; train_s shows "N s" below 120 and "N.N
min" otherwise; infer_ms shows "N.NN ms". Read every `.md` with `encoding="utf8"`, because the text
contains `×` and `°`.

### Task D2: Doc builder plus the project report (.docx)

**Goal:** the 20-page report (JIIT format: 6 pages of front matter plus 14 of body), regenerated from
source in one command.

**Step 1 (ask first):** ask the user: "The README lists `deliverables/` (progress report, project report,
slides, synopsis, papers guide), but the folder is not in the repo. Do you have the originals somewhere?"
If yes, copy them into `deliverables/originals/`, keep their wording and structure, and update only the
numbers, results and new sections. If no, write the sources from scratch as below.

**Files:** create `research/docs_build/*.py`, `research/tests/test_docs_build.py` and
`docs/deliverables_src/report.md`; output `deliverables/2_Project_Report_AeroNet.docx`.

**Builder notes (verified in a scratch run):**
- `build_docx` supports `#`, `##` and `###`; paragraphs (consecutive lines join; justified); `- ` bullets
  and `1. ` lists (styles `List Bullet` and `List Number`); pipe tables (skip the `---` row, bold first row,
  style `Table Grid`); `![caption](path)` (picture 15 cm wide, centred caption); `\pagebreak`; `**bold**`.
  Margins are 2.54 cm, Normal style Times New Roman 12.
- Add `python-docx` and `python-pptx` to `research/requirements.txt`.

**Report content (`report.md`):** the outline in 1WP §5: abstract → introduction → literature review (the
Sun et al., NeuralFoil and NNfoil contrast) → background (Euler, Cp and Cl, CST, mesh transform and
Jacobian) → method (NNfoil and the AeroNet additions: CPU fixes, positivity, O-grid, validation pipeline,
demo) → verification (the table from `docs/verification.md`, including finding 3 confirmed: `-0.5β` vs the
correct `-2β`) → results (E1–E5 tables from `results/tables.md`, and figures 1–7) → discussion (positivity
effect, sparse-mesh claim, why Prandtl-Glauert fails on the cylinder, Mach provenance) → limits → future
work → references (IEEE, only papers someone actually opened) → appendix (hyperparameters, setup). The
front matter is a cover, certificate, declaration, acknowledgement, contents and list of figures, each
followed by `\pagebreak`. Leave team names, roll numbers and the guide as `[NAME]` fields **only on the
cover and certificate pages**, and tell the user to fill them.

**Tests (`test_docs_build.py`):**
- `fill` replaces a known placeholder with `0.0123`; a missing row and an empty cell raise a KeyError that
  names both.
- `build_docx` on a small sample (heading, table, bullet, image, page break) gives 1 table and 1 inline
  shape, and the table cell text equals the filled number.
- `fmt(1450,"train_s") == "24.2 min"` and `fmt(90,"train_s") == "90 s"`.

**Acceptance:** `research/.venv/Scripts/python research/docs_build/build_all.py --check` prints `0 missing
numbers`. The report builds; opened in Word, it is 18–22 pages. Export a PDF with Word (or LibreOffice:
`soffice --headless --convert-to pdf`) to `deliverables/pdf/`.

**Commit:** `feat(docs): Markdown-to-docx builder and project report with generated numbers`.

### Task D3: Panel presentation (.pptx, 17 slides, with speaker notes)

**Files:** create `docs/deliverables_src/slides.md`; output `deliverables/3_Panel_Presentation.pptx`.

**Builder notes:** slides are separated by a line `---`. Each has `# Title`, `- ` bullets, at most one
`![](path)` and an optional `Notes:` line followed by the speaker notes. 16:9, "Title Only" layout, 22 pt
bullets. With an image, bullets go left (6 in) and the image right; without bullets the image is centred
at 10 in.

**Content:** the outline in 1WP §6, expanded to 17 slides: title → problem → what a PINN is → why airfoils
are hard (the leading edge) → mesh transformation → related work table → what AeroNet adds → verification
and bugs (positivity, CPU fixes, **mesh coefficient 4× too small**) → validation Cp figure → mesh study →
NACA 2412 polar → cylinder: PINN vs Prandtl-Glauert → speed table (measured vs quoted) → **live demo**
(the notes hold the 5-minute script from `docs/demo_script.md`) → train-your-shape → limits and future
work → conclusion and Q&A. Each slide has ≤ 5 bullets of ≤ 12 words, and every number is a placeholder.

**Tests:** `test_docs_build.py::test_pptx`: two sample slides give 2 slides, and slide 1's notes equal the
`Notes:` text.

**Acceptance:** 17 slides. Every slide that has a figure shows it. Open it in PowerPoint and check that
nothing overflows (if it does, shorten the text in `slides.md`, not the builder).

**Commit:** `feat(docs): 17-slide panel presentation with speaker notes`.
